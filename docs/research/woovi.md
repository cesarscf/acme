# Pesquisa: Woovi (ex-OpenPix) para a Cobrança por Pix da Tina

> Pesquisa feita em 2026-10-14 só com fontes primárias: docs oficiais (developers.woovi.com, páginas com "Última atualização em 14 de out. de 2026"), a spec OpenAPI oficial no GitHub ([woovibr/woovi-developers `src/swaggers/openpix.json`](https://github.com/woovibr/woovi-developers/blob/main/src/swaggers/openpix.json)), o registry do npm (`npm view`, `npm pack`), a página de preços e os termos da Woovi, e a lista de participantes do Pix do Banco Central. Nada foi testado em sandbox.

Vocabulário: **Profissional** é quem recebe; **Cliente** é quem paga; cada **Atendimento** vira uma **Cobrança**.

## TL;DR / recomendação

| Pergunta | Resposta curta |
|---|---|
| Existe "conta conectada" em que o dinheiro cai na conta do próprio Profissional? | **Sim, de dois jeitos.** (a) **Parceiro/afiliado (Split Partner)**: cada Profissional abre a **própria conta Woovi**, vinculada à plataforma. A plataforma cria o AppID dele via API, sem que ele copie nada. (b) **BaaS**: a plataforma abre, via API, uma conta Woovi em nome do Profissional (PJ ou **PF/CPF**). Os dois modelos exigem que o suporte da Woovi habilite a funcionalidade. |
| A plataforma fica fora do fluxo do dinheiro? | **Parceiro/afiliado: sim.** O saldo fica na conta do afiliado, e o parceiro só recebe a própria taxa, que pode ser zero. **BaaS: legalmente sim (a conta é do Profissional, e a custódia é da Woovi), mas operacionalmente não.** A API Master da plataforma consegue sacar e transferir da conta do Profissional, e na conta PF as tarifas são debitadas da conta da plataforma. **Subcontas/split de subconta: não.** O dinheiro cai na conta da plataforma, e a subconta é só um saldo virtual. Isso viola o requisito. |
| Pix direto para a chave Pix que o Profissional já tem no banco dele? | **Não existe.** A Cobrança Woovi sempre liquida numa conta Woovi (chave aleatória da "conta virtual"). Depois disso há saque, automático ou manual, para a chave Pix CNPJ do titular. A única forma de "usar a chave externa" é a subconta, e nela quem guarda o dinheiro é a plataforma. |
| CPF / MEI | Conta Woovi comum e afiliado: **só pessoa jurídica (MEI serve, com CCMEI)**. CPF puro só pelo **BaaS PF**, uma feature a liberar, com as tarifas pagas pela plataforma. |
| KYC / aprovação | Selfie + RG/CNH, endereço, Pix de autenticação no próprio CPF, liberação do BC Protege+ e aceite dos termos. Análise de **até 72h** (link KYC) ou **até 48h** (ativação da conta virtual). O formulário é web e mobile-first. |
| API Pix | `POST /api/v1/charge` devolve `brCode` (copia-e-cola), `qrCodeImage` e `paymentLinkUrl`. `expiresIn` tem mínimo de 5 min (o exemplo usa 86400 s). O **Cliente é opcional**, e quando é enviado basta nome + (CPF **ou** e-mail **ou** telefone). Webhook `OPENPIX:CHARGE_COMPLETED` com assinatura RSA-SHA256 (`x-webhook-signature`). Reembolso total ou parcial por API. |
| Sandbox | `app.woovi-sandbox.com` / `api.woovi-sandbox.com`. O pagamento é simulado com `GET /openpix/testing?transactionID=…`. |
| Taxas | 0,80% por Pix recebido (mín. R$ 0,50, máx. R$ 5,00) **ou** R$ 0,85 fixo. Sem mensalidade. Saque grátis a partir de R$ 500, senão R$ 1,00. Reembolso grátis. Split grátis. Envio de WhatsApp pela Woovi: R$ 0,49 (não precisamos dele). |
| SDK | `@woovi/node-sdk@1.3.3` (MIT, oficial, `node:crypto` + `fetch`, aceita `baseUrl`). Não cobre o KYC onboarding novo. REST com `Authorization: <AppID>` cru é simples o bastante. Bun: provável, mas não testado. Rate limit geral **não documentado**. |

**Recomendação.** Para o MVP, o modelo **Parceiro/afiliado** é o que melhor atende "nunca tocar no dinheiro do Profissional" e "plataforma sem taxa". A Cobrança é criada com o AppID do afiliado, e o dinheiro entra na conta Woovi do Profissional e vai para a chave Pix CNPJ dele. **O bloqueio é o CPF.** O afiliado precisa de CNPJ (MEI serve). Profissional só com CPF não entra nesse modelo. Para ele, a única saída Woovi é o BaaS PF, que coloca a plataforma no caminho das tarifas e dá a ela poder técnico de saque. Os dois modelos dependem de habilitação comercial pela Woovi, então convém falar com o suporte antes de decidir.

## 1. Modelo de contas para plataformas

### 1.1 Parceiro / afiliado (Split Partner): cada Profissional com a própria conta Woovi
- A funcionalidade de parceiro **precisa ser ativada pelo suporte** ([Como integrar como parceiro](https://developers.woovi.com/docs/partnerships/how-to-integrate-as-woovi-partner); [Cadastrando Empresas Parceiras](https://developers.woovi.com/docs/split/partner-config)).
- Há quatro jeitos de vincular um afiliado: **link de afiliado** (`https://app.woovi.com/register?partner=…`), cadastro em lote por Excel, formulário "Nova Empresa" ou **API** `POST /api/v1/partner/company` (pré-registro com `preRegistration` {nome, CNPJ, site} + `user` {nome, e-mail, telefone, CPF}) ([criar afiliado via API](https://developers.woovi.com/docs/partnerships/how-to-create-a-affiliate-company-via-api)). O pré-registro fica "Dados pendente" até o afiliado completar o cadastro (mesma página).
- O afiliado valida o e-mail e o telefone (SMS ou WhatsApp) e **completa os próprios dados de cadastro** ([Como integrar como parceiro](https://developers.woovi.com/docs/partnerships/how-to-integrate-as-woovi-partner)).
- **Sem copiar chave de API.** O parceiro cria a application do afiliado via `POST /api/openpix/v1/partner/application` (`application.type` = `API`, `taxID` do afiliado) e recebe `clientId`/`clientSecret`. O AppID é `base64(clientId:clientSecret)` ([acessar a API com empresa afiliada](https://developers.woovi.com/docs/partnerships/how-to-access-api-via-affiliated-company)). Com esse AppID, o parceiro cadastra os webhooks do afiliado ([webhook para afiliado](https://developers.woovi.com/docs/partnerships/how-to-create-a-webhook-to-affiliated-company)).
- Fluxo do dinheiro: "Cada afiliado possui conta virtual na plataforma registrada no CNPJ de sua empresa independente do parceiro. Cada afiliado recebe valores de cobranças diretamente via pix em sua conta virtual… **O parceiro não recebe diretamente valores em sua conta, somente taxa do parceiro**" ([Split: introdução](https://developers.woovi.com/docs/splits/split-introduction)).
- A taxa do parceiro é configurável. Com "**Usar taxa padrão da plataforma**", o afiliado paga só a tarifa Woovi do plano dele, "sem valor adicional referente a taxa do parceiro" ([Configurando taxa de parceiro](https://developers.woovi.com/docs/split/partner-config-fee)). Isso atende "plataforma sem taxa".
- **Só CNPJ.** Os exemplos e o schema usam `BR:CNPJ` no pré-registro e na application ([OpenAPI](https://github.com/woovibr/woovi-developers/blob/main/src/swaggers/openpix.json), `/api/v1/partner/company`). A doc de conta PF diz que `BR:CPF` "não pode ser combinado com `partner: true` (uma pessoa física não tem empresa afiliada)" ([conta PF](https://developers.woovi.com/docs/baas/kyc/kyc-api-onboarding-conta-pf)). Os termos de abertura de conta exigem que o usuário seja "pessoa jurídica devidamente constituída e registrada" ([Termos](https://woovi.com/politicas/termos/)).

### 1.2 BaaS: a plataforma abre contas Woovi para os Profissionais
- A Woovi descreve o BaaS assim: "você cria contas digitais para seus clientes, com a sua marca". Cada conta tem "saldo próprio e isolado, chaves Pix, extrato e o próprio AppID". A conta principal tem a **API Master**, que "cria contas e gera as credenciais de cada conta" ([Visão geral do BaaS](https://developers.woovi.com/docs/baas/conceitos-baas)).
- Pré-requisitos: conta Woovi ativa **com CNPJ**, caso de uso avaliado pela Woovi e as features BaaS + Criação de conta, ativadas pelo suporte em "até 2 dias úteis" ([Ativando o modo BaaS](https://developers.woovi.com/docs/baas/ativacao-baas)).
- Onboarding: `POST /api/v1/kyc/onboarding` recebe o CNPJ (ou CPF) e devolve um `linkOnboarding` hospedado pela Woovi. O link aceita `redirectUrl`, iframe e `?embed=true` (esconde o logo Woovi, mas os termos continuam citando a "WOOVI INSTITUIÇÃO DE PAGAMENTO LTDA.") ([criar onboarding](https://developers.woovi.com/docs/baas/kyc/kyc-api-onboarding-create); [incorporar](https://developers.woovi.com/docs/baas/kyc/kyc-api-onboarding-embed); [white-label](https://developers.woovi.com/docs/baas/kyc/kyc-api-onboarding-white-label)). Há também o fluxo [100% via API](https://developers.woovi.com/docs/baas/kyc/kyc-api-onboarding-full-api). Depois da aprovação (webhook `ACCOUNT_REGISTER_APPROVED` com `accountId`), a API Master cria o AppID da conta via `POST /api/v1/application`, inclusive com `scopes` ([Fluxo básico](https://developers.woovi.com/docs/baas/basic-flux-baas)).
- **Conta PF (CPF)**: mesmo endpoint, com `taxIDType: "BR:CPF"` + `officialName`. "A conta PF não vem habilitada por padrão… A liberação passa por aprovação interna. **Na conta PF, o titular nunca paga tarifas: todas as tarifas da conta são cobradas da conta padrão da sua empresa**." O erro sem a liberação cita as features `BAAS`, `BAAS_PF_ACCOUNT` e `BAAS_FEE_FROM_DEFAULT_ACCOUNT` ([conta PF](https://developers.woovi.com/docs/baas/kyc/kyc-api-onboarding-conta-pf)).
- **Poder da API Master sobre o saldo**: `POST /api/v1/account/{accountId}/withdraw` com a API Master "envia o saldo da conta para a conta bancária de destino configurada para ela", e a chave de saque (`pixKeyWithdraw`) "pode ser definida pela API". Também há transferência entre contas, inclusive no sentido conta principal → conta de cliente, com habilitação adicional ([Saque, transferência e extrato](https://developers.woovi.com/docs/baas/movimentando-saldo)).

### 1.3 Subcontas (SPLIT_SUB_ACCOUNT): **não serve**
- A subconta é criada só com `name` + `pixKey`, e a chave "não precisa ser necessariamente atrelada a uma conta da woovi" ([criar subconta](https://developers.woovi.com/docs/subaccount/how-to-create-a-subbaccount)). Por isso parece o "use a chave Pix do banco do Profissional", mas o dinheiro fica com a plataforma.
- "Subcontas **não são contas bancárias reais** e somente transacionam valores virtuais… os valores sacados só serão debitados da **conta principal** no momento do saque" ([Split: introdução](https://developers.woovi.com/docs/splits/split-introduction)). O saque para a chave é um `POST /api/v1/subaccount/{id}/withdraw` feito pela plataforma ([saque de subconta](https://developers.woovi.com/docs/subaccount/how-to-withdraw-from-subaccount-using-api)).
- Conclusão: o Cliente paga para a conta da plataforma, e a plataforma depois repassa. Isso viola o requisito.

### 1.4 Liquidação direta numa chave Pix externa
- Não encontrei esse modo. A conta virtual "gera uma chave Pix aleatória em nome da sua empresa… utilizada em todas as cobranças". O saldo vai para "a chave Pix CNPJ da sua empresa" ([FAQ Conta Virtual](https://developers.woovi.com/docs/faq/faq-virtual-account)). O saque é automático diariamente às 19h para valores a partir de R$ 500 (mínimo configurável), ou manual a qualquer momento. "Por razões de segurança os saques só podem ser realizados na chave Pix do seu CNPJ" ([FAQ Saques](https://developers.woovi.com/docs/faq/faq-withdraw)). Exceção: no BaaS, a chave de saque é configurável por API (§1.2).

### 1.5 CPF, MEI, KYC e prazo
- **MEI**: no KYC, "MEI não precisa de documentos da empresa — apenas os dos sócios". O passo `SOCIAL_CONTRACT` aceita o CCMEI no caso de MEI. Cada representante envia **selfie + CNH ou RG** ([Documentos e compliance (KYC)](https://developers.woovi.com/docs/baas/documentos-kyc); [100% via API](https://developers.woovi.com/docs/baas/kyc/kyc-api-onboarding-full-api); [webhooks do ciclo de vida](https://developers.woovi.com/docs/baas/kyc/kyc-webhooks-lifecycle)). O RG só é aceito se emitido a partir de 2015 (com o titular já adulto), e a CNH vale mesmo vencida ([Central de ajuda: documento de identificação](https://ajuda.woovi.com/hc/duvidas-frequentes/articles/documento-de-identificacao-valido-para-abertura-da-conta-virtual)).
- Passos do onboarding (11 no PJ): dados da empresa, endereço, contrato social/CCMEI, sócios, **BC Protege+**, termos, documento do sócio, **selfie (facematch)**, endereço do sócio e **autenticação Pix** (o sócio paga um Pix simbólico do próprio CPF, e o valor é devolvido) ([webhooks do ciclo de vida](https://developers.woovi.com/docs/baas/kyc/kyc-webhooks-lifecycle); [100% via API §5–6](https://developers.woovi.com/docs/baas/kyc/kyc-api-onboarding-full-api)). Na conta PF: dados, endereço, documento de identidade e selfie, sem contrato social ([conta PF](https://developers.woovi.com/docs/baas/kyc/kyc-api-onboarding-conta-pf)).
- **Prazo**: a análise "pode levar até 72h" no KYC ([documentos KYC](https://developers.woovi.com/docs/baas/documentos-kyc)), e a ativação da conta virtual é feita "em até 48h" ([FAQ Conta Virtual](https://developers.woovi.com/docs/faq/faq-virtual-account)). O cadastro pode voltar para PENDING via RFI várias vezes ([webhooks do ciclo de vida](https://developers.woovi.com/docs/baas/kyc/kyc-webhooks-lifecycle)).

## 2. Quem custodia o dinheiro em cada modelo

- **Status regulatório da Woovi (fonte BCB)**: na lista de participantes ativos do Pix de 14/10/2026, a linha é "WOOVI IP LTDA.; ISPB 54811417; CNPJ 54.811.417/0001-63; Instituição de Pagamento; **Autorizada pelo BCB: Sim**; participação **Direta** no SPI; **Provedor de Conta Transacional**" ([BCB, lista de participantes do Pix, CSV de 2026-10-14](https://www.bcb.gov.br/content/estabilidadefinanceira/participantes_pix/lista-participantes-instituicoes-em-adesao-pix-20261014.csv)).
- Nos termos da Woovi (não é fonte regulatória), o saldo fica numa conta de pagamento em nome do usuário, "cujos valores… serão geridos e custodiados pela WOOVI". A Woovi pode reter valores em certos casos, como risco ou ordem judicial ([Termos, versão de 10/04/2025](https://woovi.com/politicas/termos/)). A Woovi também mantém uma "reserva de segurança" de parte do saldo para devoluções por fraude ([FAQ Saques](https://developers.woovi.com/docs/faq/faq-withdraw)).

| Modelo | Onde o dinheiro do Cliente cai | Quem custodia | A plataforma fica fora? |
|---|---|---|---|
| Parceiro/afiliado (taxa de parceiro = padrão) | Conta Woovi do Profissional (CNPJ dele), depois saque para a chave Pix CNPJ dele | Woovi IP, na conta de pagamento do Profissional | **Sim.** A plataforma não recebe nada e não paga tarifa. Ela tem um AppID do afiliado: a confirmar quais escopos ele tem (o AppID é de "API" e o escopo padrão não está documentado) |
| BaaS PJ | Conta Woovi do Profissional aberta pela plataforma | Woovi IP | **Parcial.** A plataforma não recebe, mas a API Master **consegue sacar, transferir e mudar a chave de saque** |
| BaaS PF (CPF) | Conta Woovi PF do Profissional | Woovi IP | **Parcial.** Igual ao BaaS PJ, e as **tarifas saem da conta da plataforma** (a plataforma precisaria recobrar do Profissional ou absorver) |
| Subconta / split de subconta | **Conta da plataforma**. A subconta é um saldo virtual | Woovi IP, em nome da **plataforma** | **Não.** Viola o requisito |

- **Incerteza regulatória**: não achei uma fonte primária do BCB dizendo se o modelo de subconta (a plataforma recebe e depois repassa) obrigaria a plataforma a ter autorização como instituição de pagamento. Também não achei uma que diga como o BCB enquadra o poder de saque da API Master no BaaS. Isso precisa de uma opinião jurídica, se esses modelos forem considerados.

## 3. API Pix

- **Criar Cobrança**: `POST /api/v1/charge`. Os campos obrigatórios são só `value` (centavos) e `correlationID`. A resposta traz `brCode` (copia-e-cola), `qrCodeImage` (URL da imagem), `paymentLinkUrl`, `expiresIn` (86400 no exemplo) e `status: ACTIVE` ([criar cobrança](https://developers.woovi.com/docs/charge/how-to-create-charge-using-api)). Há também `GET /openpix/charge/brcode/image/{id}.png` ([OpenAPI](https://github.com/woovibr/woovi-developers/blob/main/src/swaggers/openpix.json)). A query `return_existing=true` deixa a criação idempotente por `correlationID` (mesma fonte).
- **Expiração**: `expiresIn` em segundos ("minimum is 5 minutes") ou `expiresDate` em ISO 8601. O tipo `OVERDUE` aceita vencimento, multa, juros e desconto ([OpenAPI](https://github.com/woovibr/woovi-developers/blob/main/src/swaggers/openpix.json), schema de `POST /api/v1/charge`). O prazo padrão também é configurável no painel ([expiração](https://developers.woovi.com/docs/charge/how-to-charge-expiration)). Uma Cobrança aceita só 1 pagamento ([conceito](https://developers.woovi.com/docs/concepts/charge)).
- **Dados do Cliente**: "Customer field is not required. However, if you decide to send it, you must send at least one of: name + taxID **or** name + email **or** name + phone" ([OpenAPI](https://github.com/woovibr/woovi-developers/blob/main/src/swaggers/openpix.json), `CustomerPayload`). **O CPF não é obrigatório.** Nome + telefone do WhatsApp bastam. `ensureSameTaxID` permite exigir que o pagador tenha o mesmo CPF do Cliente ([bloquear CPF diferente](https://developers.woovi.com/docs/charge/how-to-block-payment-different-taxid)).
- **Webhooks**: são cadastrados via `POST /api/v1/webhook` (um evento por cadastro). Eventos relevantes: `OPENPIX:CHARGE_CREATED`, `OPENPIX:CHARGE_COMPLETED`, `OPENPIX:CHARGE_EXPIRED`, `OPENPIX:CHARGE_COMPLETED_NOT_SAME_CUSTOMER_PAYER`, `OPENPIX:TRANSACTION_RECEIVED`, `OPENPIX:TRANSACTION_REFUND_RECEIVED` e os `PIX_TRANSACTION_REFUND_*` ([OpenAPI](https://github.com/woovibr/woovi-developers/blob/main/src/swaggers/openpix.json), `WebhookEventEnum`; [webhook para afiliado](https://developers.woovi.com/docs/partnerships/how-to-create-a-webhook-to-affiliated-company)). No cadastro há um handshake (a URL precisa responder 200, ou usa-se `?validate=false`) ([Webhooks por conta](https://developers.woovi.com/docs/baas/webhooks-por-conta)). Com muitas contas, é possível usar um único endpoint e identificar a conta pelo path, pelo header `authorization` ou pelo bloco `account` do payload (mesma fonte).
- **Assinatura**: o recomendado é `x-webhook-signature`, **RSA-SHA256** em base64 com a chave pública da Woovi (a mesma para todos os webhooks, disponível em `GET /api/v1/webhook/public-keys`). O `X-OpenPix-Signature` (HMAC-SHA1) está marcado como depreciado ([validação x-webhook-signature](https://developers.woovi.com/docs/webhook/seguranca/webhook-signature-validation); [HMAC (depreciado)](https://developers.woovi.com/docs/webhook/seguranca/webhook-hmac)).
- **Reembolso**: `POST /api/v1/charge/{correlationID}/refund` com `correlationID` próprio (idempotência), `value` opcional (parcial) e `comment` ≤ 140 caracteres ([criar reembolso](https://developers.woovi.com/docs/refund/charge-refund-create-api)). O reembolso é total ou parcial ([conceito](https://developers.woovi.com/docs/concepts/refund)).
- **Sandbox**: é um cadastro separado em `https://app.woovi-sandbox.com/` ("Os dados de produção não funcionam no ambiente de testes") ([ambiente de teste](https://developers.woovi.com/docs/test-environment)). A API é `https://api.woovi-sandbox.com` ([OpenAPI](https://github.com/woovibr/woovi-developers/blob/main/src/swaggers/openpix.json), `servers`). Para **simular o pagamento**: `curl 'https://api.woovi.com/openpix/testing?transactionID=<identifier>' -H 'Authorization: <appID>'`, que dispara o webhook ([pagar cobrança de teste](https://developers.woovi.com/docs/test-environment/test-account/test-pay-pix)). A doc mostra o host de produção nesse exemplo, ver §Pontos em aberto. A conta de teste suporta cobrança, reembolso e reembolso parcial, mas não saque ([intro conta de teste](https://developers.woovi.com/docs/test-environment/test-account/introduction-to-test-account)). No sandbox, a autenticação Pix do KYC não se aplica ([100% via API](https://developers.woovi.com/docs/baas/kyc/kyc-api-onboarding-full-api)). Há também contas especiais para simular erros de envio de Pix ([simulação de erros](https://developers.woovi.com/docs/flows/sandbox-error-simulation)).

## 4. Taxas

Fonte: [woovi.com/pricing](https://woovi.com/pricing/), salvo indicação.

| Item | Valor |
|---|---|
| Pix recebido, Plano Percentual | **0,80%** por Pix confirmado (mín. R$ 0,50, máx. R$ 5,00) |
| Pix recebido, Plano Fixo | **R$ 0,85** por Pix confirmado |
| Mensalidade / adesão | Nenhuma ("Sem mensalidade, sem taxa de adesão") |
| Saque | Grátis a partir de R$ 500. R$ 1,00 abaixo disso ([FAQ Saques](https://developers.woovi.com/docs/faq/faq-withdraw)) |
| Reembolso / reembolso parcial | Grátis ([FAQ Conta Virtual](https://developers.woovi.com/docs/faq/faq-virtual-account)) |
| API Pix / Split | Grátis |
| Pix enviado | R$ 1,00 |
| WhatsApp pela API oficial da Woovi | R$ 0,49 por mensagem (a Tina já envia pelo nosso WhatsApp, então não precisamos) |

- **Para o Profissional (afiliado)**: paga o plano dele. Exemplos: Atendimento de R$ 150 → R$ 1,20 (0,8%) ou R$ 0,85 (fixo); de R$ 50 → R$ 0,50 (mínimo) ou R$ 0,85. Sem mensalidade. O saque automático diário é grátis a partir de R$ 500.
- **Para a plataforma**: no modelo parceiro com "taxa padrão", **custo zero e receita zero** ([taxa de parceiro](https://developers.woovi.com/docs/split/partner-config-fee)). No BaaS PF, a plataforma **paga as tarifas** das contas PF ([conta PF](https://developers.woovi.com/docs/baas/kyc/kyc-api-onboarding-conta-pf)). Não achei preço público de BaaS nem do plano "Alto Volume" (é preciso falar com vendas).

## 5. SDK, autenticação e limites

- **Auth**: header `Authorization: <AppID>`, cru e sem `Bearer` ([Começando com a API](https://developers.woovi.com/docs/apis/api-getting-started)). O AppID equivale a `base64(clientId:clientSecret)` ([acessar API via afiliada](https://developers.woovi.com/docs/partnerships/how-to-access-api-via-affiliated-company)). Criar o AppID no painel exige 2FA (mesma fonte de "Começando"). Os IPs e certificados da API mudam, por isso não devem ser fixados (mesma fonte).
- **SDK oficial**: `@woovi/node-sdk`, `latest` = **1.3.3** (publicado em 2025-11-06), MIT, repositório [woovibr/woovi-nodejs-sdk](https://github.com/woovibr/woovi-nodejs-sdk) (último push em 2026-02-12). Única dependência: `@woovi/apiwithlog` (`npm view @woovi/node-sdk`). A doc diz que é "mantido oficialmente pela woovi" ([O que é o SDK de Node](https://developers.woovi.com/docs/sdk/node/sdk-node-what-is)). Recursos: `charge`, `chargeRefund`, `customer`, `webhook` (com `webhook.handler({ onChargeCompleted, … })`), `partner` (`createPreRegistration`, `createApplication`), `subAccount`, `account`, `application`, `accountRegister` ([uso](https://developers.woovi.com/docs/sdk/node/sdk-node-usage); `dist/index.d.ts` do pacote). **Não há método para `/api/v1/kyc/onboarding`** no 1.3.3.
- **Sandbox no SDK**: a doc manda editar a constante `API_BASE_URL` no código-fonte ([configurar sandbox](https://developers.woovi.com/docs/sdk/node/how-to-configure-for-sandbox)). No pacote 1.3.3, porém, `ApiConfig` já aceita `baseUrl?: string` (`clientConfig.baseUrl ?? API_BASE_URL` em `dist/index.mjs`).
- **Bun**: o SDK usa só `node:crypto` e `fetch` (inspeção do `npm pack`), e ambos existem no Bun. Não há declaração oficial de suporte nem teste nosso. Como a API é REST + JSON com um header, chamar com `fetch` direto do Elysia é trivial, e a assinatura RSA pode ser verificada com `node:crypto`.
- **Rate limits**: **não há um limite geral de requisições documentado** (busquei "rate limit"/"429" na spec OpenAPI e nas docs). O único limite documentado é o **token bucket de consultas de chave Pix ao DICT**: 500 tokens de teto, +20/min, chave inexistente custa 20 tokens, e abaixo de 20 tokens até pagamentos por QR são bloqueados com 429 ([Token Bucket](https://developers.woovi.com/docs/payment/pix-key-token-bucket)). Ele não afeta a criação de Cobrança, só pagamentos e saques por chave.

## 6. UX de onboarding do Profissional

**Modelo parceiro/afiliado (Profissional MEI/CNPJ)**:
1. No nosso app: "Conectar Pix". O backend chama `POST /api/v1/partner/company` com os dados que já temos (CNPJ, nome, e-mail, celular, CPF) ([criar afiliado via API](https://developers.woovi.com/docs/partnerships/how-to-create-a-affiliate-company-via-api)).
2. O Profissional valida o e-mail (link) e o celular (código por SMS ou WhatsApp) e cria a senha ([Como integrar como parceiro](https://developers.woovi.com/docs/partnerships/how-to-integrate-as-woovi-partner); [Central de ajuda: cadastrar empresa](https://ajuda.woovi.com/hc/duvidas-frequentes/articles/como-cadastrar-minha-empresa)).
3. Ele completa o cadastro: documentos, selfie, BC Protege+ (pode ser preciso **abrir o app do banco dele** para desativar), autenticação Pix e termos. Os passos e os documentos estão em §1.5. O fluxo do afiliado não tem página com a lista de passos. Assumi que ele segue o mesmo KYC, mas isso é **inferência** (ver Pontos em aberto).
4. Análise: até 48–72h.
5. O backend cria o AppID (`/partner/application`) e o webhook. Nada é copiado pelo Profissional.

**Modelo BaaS (PJ ou PF)**: um link de KYC (`linkOnboarding`) aberto dentro do app (WebView/iframe com `allow="camera"`, `?embed=true`). O formulário é "otimizado para telas estreitas/mobile" ([incorporar](https://developers.woovi.com/docs/baas/kyc/kyc-api-onboarding-embed)). Os passos são os de §1.5. Na PF: dados, endereço, documento e selfie. Ao final há `redirectUrl` e os webhooks `ACCOUNT_REGISTER_*`. A doc avisa que "upload de arquivos dentro de iframe pode ter restrições em alguns navegadores mobile" (mesma fonte). Ponto positivo: no PJ, os dados da empresa e dos sócios vêm pré-preenchidos pelo CNPJ ([criar onboarding](https://developers.woovi.com/docs/baas/kyc/kyc-api-onboarding-create)).

**Resumo de esforço**: nenhum dos dois modelos é "conectar em poucos toques". Há KYC regulatório completo (selfie + documento + Pix de autenticação + BC Protege+) e espera de até 72h. **Tudo pode ser feito no celular, pela web**, e não é preciso baixar o app da Woovi. A vantagem real é que **não há chave de API para copiar**: a plataforma provisiona as credenciais via API.

## Pontos em aberto / incertezas

1. **Habilitação comercial**: Parceiro, BaaS, conta PF e KYC_ONBOARDING_LINK dependem do suporte da Woovi, e o BaaS envolve avaliação do caso de uso. Não há preço público para BaaS nem para conta PF. Precisa de contato comercial.
2. **CPF puro**: o único caminho Woovi é o BaaS PF, e nele as tarifas são debitadas da plataforma (`BAAS_FEE_FROM_DEFAULT_ACCOUNT`). Falta saber se dá para repassar o custo ao Profissional sem a plataforma "tocar no dinheiro", e se existe outra configuração. Perguntar à Woovi.
3. **Escopos do AppID do afiliado**: `POST /partner/application` não documenta `scopes`. Precisa confirmar se dá para limitar a `CHARGE_*`/`WEBHOOK_*` (sem saque/pagamento), para que a plataforma não tenha poder técnico sobre o saldo do Profissional. No BaaS, `POST /api/v1/application` aceita `scopes`, mas a API Master continua podendo sacar.
4. **KYC do afiliado**: não há página que liste os passos do cadastro completo do afiliado (parceiro). Assumi o mesmo KYC PJ (selfie, documento, BC Protege+, autenticação Pix). Isso é inferência.
5. **Saque do afiliado**: o FAQ diz que o saque vai só para a chave Pix **CNPJ**. Um MEI sem chave CNPJ cadastrada no banco teria que criar uma. Não está claro se a chave pode ser CPF no MEI.
6. **Simulação de pagamento**: a doc mostra `https://api.woovi.com/openpix/testing` com o AppID da conta de teste, mas o ambiente é `api.woovi-sandbox.com`. Precisa validar qual host usar.
7. **Rate limit geral da API**: não documentado.
8. **Bun**: o SDK provavelmente funciona (`fetch` + `node:crypto`), mas não foi testado. O SDK também não cobre o KYC onboarding.
9. **Regulatório**: confirmado pelo BCB que a Woovi IP LTDA. é instituição de pagamento autorizada e participante direta do Pix. Não verifiquei em fonte BCB se os modelos subconta ou BaaS-com-poder-de-saque criam obrigação regulatória para a plataforma. Isso precisa de parecer jurídico.
10. **Inconsistência nos termos**: o contrato traz "WOOVI INSTITUIÇÃO DE PAGAMENTO LTDA." no corpo e "S.A." no anexo ([Termos](https://woovi.com/politicas/termos/)). O BCB lista "WOOVI IP LTDA.".
11. **Retenção**: os termos permitem reter saldo (risco, ordem judicial), e há "reserva de segurança" por fraude. O percentual não foi encontrado.
